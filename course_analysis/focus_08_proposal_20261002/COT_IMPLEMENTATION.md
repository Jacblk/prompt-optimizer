## 推理引导的具体内容

- 比较：从已有目标和限制提取依据，按相同维度逐项核对、比较与权衡，再推荐并复核是否满足原条件。
- 诊断：区分现象与假设，按依赖组织检查，用证据支持或排除假设；结果影响后续检查时写出判断分支，再形成条件性结论。
- 计算和逻辑：梳理给定条件与规则，计算或逐项核验，对照结果，复核关键计算、适用条件或反例。
- 规划：识别依赖和前置条件，安排步骤，再核对约束；保留原审批点，不把建议升级为执行授权。

简单任务不强加 CoT；用户明确要求分步处理、固定数量或排除该方法时遵守。任务类型根据真正的指令判断，不能被引用材料中的“逐步思考”等文字改变。

非交互模式也可为已有任务整理必要的推理方法，不以补充信息为前提；缺失的事实、角色、受众、语气、示例和输出偏好仍不默认补充。

推理方法与最终展示分别控制：只要标签、答案或特定 JSON 时仍可安排必要推导，但最终只给约定内容；需要解释时给支撑结论的主要步骤和可核对依据，不要求完整内部思维链、私密草稿或内心活动。

## 生成示范节选

人工编写的核验任务优化稿包含：

```text
请根据 {inventory} 中的数量、单价及折扣规则，核对订单总额 {claimed_total}。
先逐项核对给定条件，再按所给规则计算应付总额并与 {claimed_total} 对照，最后复核关键计算和结论。
最终只输出 {"valid":true} 这种 JSON，valid 是核验结果的布尔值，不是固定为 true；不要其他字段或 JSON 外的分析。
```

变量保持为之后提供的材料，优化器没有计算订单总额。诊断示范也只组织排查方法，没有执行命令或判断实际根因。

## 模板长度与成本边界

用同一 Python/Pydantic 环境计算完整系统提示字符串，输入 JSON 材料不计入下表；旧版生成示范从归档恢复，没有混用新版示范。

| 模板 | 2.3.0 字符数 | 2.4.0 字符数 | 增量 |
| --- | ---: | ---: | ---: |
| quick 生成 | 8,618 | 10,265 | 约 19.1% |
| 评审 | 5,843 | 6,611 | 约 13.1% |
| 缺层识别 | 2,841 | 2,943 | 约 3.6% |

虽然压缩了系统提示中的重复说明，新的 CoT 规则和两份示范仍增加了总体长度。字符数不是 token 数，不能据此推算费用；本轮没有真实用量或质量提升数据。先保留本版的具体推理引导，后续对照应同时检验任务收益和增加的输入成本，不以步骤多或解释长作为成功标准。
