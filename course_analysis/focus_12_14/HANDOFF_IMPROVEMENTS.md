## 输出与报告

最终提示的顺序为：本轮任务 → 任务执行/交付要求 → 交接上下文 → 参考依据 → 接续执行提醒。程序直接组装固定块，生成器不负责重新抄写；提醒始终在末尾，正式输入和完整候选继续受字符及各角色窗口预算约束。

`details` 每项包含 `kind`、`value` 和 `citation`；引文同时出现在所属条目的 `citations`。例如期限值保持“下周二前”，不扩写为具体日期。合并重复条目时仍保留不同来源位置的细节和引文，替代项保留其旧依据而不列为当前有效要求。

完整报告保存结构化条目、细节、引文位置、任务绑定摘要、固定块和所有阶段用量；模型输入使用固定块及摘要标识，不重复整份结构化台账或原始历史。建议与待批准记录继续作为状态/依据，不自动成为执行授权。

新增测试检查末尾有效约束、状态不升级、负责人/日期/依赖的原文定位、归并遗漏或改类被拒、独立替代裁判拒绝期限和负责人误读、任务绑定与隔离、修复和最终评审收到同一快照。原有回环接口继续用实际 LangChain 适配器和 OpenEvals 走完严格交接。

首次针对性测试发现两项夹具错误：修复裁判引用了测试任务没有提供的“不改文件”，以及手写块 ID 未使用已有的四位编号；修正输入和断言后两次验收均通过。没有放宽引用或覆盖校验。

固定摘要和替代裁判验证工程约束、失败处理及材料传输，不能证明真实模型理解了每个日期、没有遗漏，或下游任务准确率提高。姓名在引文中出现的本地检查无法判断是否被指派，时间值是否存在也无法单独证明修饰关系；质量模式必须依赖逐阶段语义核验，快速模式仍明确未经独立保真评审。本轮未读取真实 `.env`、调用外部模型、开展真实摘要质量或成本评测。新增末尾提醒会增加输入长度，未声称降低 token 消耗。
