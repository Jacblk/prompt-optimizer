# 提示词优化器

把自由描述整理成提示词，保留原意、权限、例外、操作顺序、材料引用和输出格式。只交付提示词，不执行其中的任务。

提供**对话式 TUI 和 CLI**，共用需求澄清、A/B 生成和 C 独立评审。双击 `启动提示词优化器.cmd` 打开 TUI；命令行使用 `prompt-optimizer.cmd` 或 `cli.py`。没有历史时普通生成，有历史时自动交接，无需选择流程或模式。

## 启动

首次下载后，在项目目录创建环境并安装依赖：

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

填好 `.env` 中的三组模型配置后，双击 `启动提示词优化器.cmd`，或执行：

```powershell
& .\.venv\Scripts\python.exe -X utf8 tui.py
```

同一个环境只安装一次；后续直接启动即可。`requirements.txt` 固定全部直接依赖版本，旧 `requirements-tui.txt` 安装同一组依赖。本机已验证 Windows 11 x64 / Python 3.14.7；代码要求 Python 3.11+，其他版本和平台的完整兼容性尚未验证，详见[兼容性记录](COMPATIBILITY.md)。

`launcher.py` 和旧文件名 `optimize.py` 继续打开同一个 TUI；命令行需求使用独立的 `cli.py`。缺少依赖时，启动器给出一次性安装命令，不会每次重新安装。

## CLI

在项目目录运行，无需安装额外依赖：

```powershell
.\prompt-optimizer.cmd "帮我优化：只读检查 src 中的异常处理，输出问题清单"
.\prompt-optimizer.cmd --input .\request.md --output .\result.md
.\prompt-optimizer.cmd --input .\request.md --non-interactive --json
.\prompt-optimizer.cmd --help
```

直接运行 `.\prompt-optimizer.cmd` 可输入多行需求，以单独一行 `END` 提交。终端中可逐轮回答澄清问题；管道或输出重定向时默认不等待回答，需要确认就保存报告并返回退出码 `3`。`--interactive` 可在输出重定向时显式允许终端回答。

stdout 默认只有成功提示词，`--json` 输出完整结果、用量、问题和保存路径；进度与错误写入 stderr。默认配置、报告目录和上次成功提示词都位于项目目录；显式传入的相对路径按当前工作目录解析。详细参数、管道、材料和交接示例见 [CLI 使用说明](CLI_WORKFLOW.md)。

## 模型配置

按 `.env.example` 将需要的设置填入项目 `.env`，已有配置可以继续使用。模型名称和服务地址使用服务商实际提供的值。

- 使用 `GENERATOR_A`、`GENERATOR_B`、`JUDGE` 三组配置，每组需要 `_NAME`、`_API_KEY`、`_BASE_URL`；分别负责 A/B 生成和 C 独立评审。缺少任一组时会明确提示。
- 使用 Chat Completions 兼容的 API 基地址；不要填完整的 `/chat/completions` 请求地址。

每组配置可分别设置以下秒数；已有配置缺少提醒项时使用默认值，不必修改真实 `.env`。

| 配置后缀 | 默认值 | 作用 |
| --- | --- | --- |
| `_TIMEOUT` | 90 | 限制连接、发送和连接池等待；不限制模型响应读取或流片段间隔 |
| `_SLOW_WARNING_SECONDS` | 90 | 连续无有效活动时显示“等待较久”，继续等待；新活动会清除提醒 |

例如 `JUDGE_SLOW_WARNING_SECONDS=180` 只调整 C 的提醒阈值。秒数必须为有限数值且至少 0.1；`_TIMEOUT` 仍最多为 3600 秒。流式参数由程序管理，`_EXTRA_BODY` 不能覆盖 `stream` 或 `stream_options`。

启动主界面、预览材料、回看报告都不读取模型配置或调用模型。发送有效需求时才准备配置。交接缺少模型上下文窗口时，界面会提示填写；全部通过核验后保存到公开的 `context_windows.json`，不保存凭据。

## 使用

1. 在下方橙色多行输入区填写需求、待优化的提示词或补充，支持中文、英文及混合输入；Enter 换行，点击发送或按 F2 提交。
2. 需要确认时，弹窗每轮最多问三个关键问题。可以自由回答、明确选择建议选项、部分回答、暂停或取消。空回答不会采用建议。
3. 模型判断信息足够时自动生成；仍有关键缺口时继续弹出问题。结果完成后发送补充可继续同一会话；更换独立任务时点击“新会话”。
4. 上方绿色“提示词结果 / 草稿（只读）”区域展示生成结果，不能直接输入。最终提示词可以复制、保存；待确认内容可另存草稿。“回看报告”离线打开已保存结果，不调用模型。

提示词直接使用 Markdown，按任务需要组织为四层：

| 层次 | 内容 |
| --- | --- |
| 指令层 | 任务目标、操作范围、权限、约束和必要步骤 |
| 情境层 | 背景、当前状态、环境和待处理输入 |
| 参考层 | 可借鉴的代码、实现、文件、模板、规范或执行记录，注明用途和遵循范围 |
| 输出层 | 交付物、验收要求、格式、语言和表达要求 |

复杂且包含多类信息的改写稿按上述顺序为有内容的层明确分段。短任务保持简洁，可选层没有内容时省略；不为凑齐标题编造背景或示例。参考层无需输入/输出示例。待修改代码和事实依据属于情境，借鉴的实现与模板属于参考；操作限制和遵守规范的要求放指令，交付、格式与验收要求集中放输出。同一材料兼具多种用途时只保留一份原文，以交叉引用说明其他用途。用户明确指定提示词自身格式时优先遵守，下游的 JSON、标签等输出要求完整保留。

指令层说明步骤时使用从 `1.` 开始的连续编号，每步独占一行，步骤之间用换行隔开，不把多个步骤串在同一段。步骤数量按任务需要确定，简单任务不为编号而强行增加步骤；这条规则不改变下游回答格式。

只追问影响目标、方向、范围、权限或验收的缺口，不强制补齐语气、角色或受众。原始需求、补充、纠正和明确采用的建议分别保留；生成、评审、修复共同使用已确认需求。

A/B 在同一次生成中完成用途识别、分段组织、独立层边界核对、主动去冗余及需求复核，检查内容错层、用途混淆、同层重复、跨层复述、重复步骤和套话。只有信息与作用都重复、合并不改变原意时才精简；精简后对照完整已确认需求核对约束。修复同样执行这些检查，不增加专门的分层或精简调用。

C 独立评审 A/B 和原文，核对保真、权限、事实、材料及格式，并独立检查层边界，再检查重复与冗余、内部一致性、约束作用域、步骤有效性、交付一致性和改写收益。实质错层或用途混淆以带引文的 `layer_boundary` 问题指出正确归属和最小调整方式；已经改变权限、事实或格式的问题仍使用相应类别。必要的任务定位、不同用途的复述和用户要求的重复强调可以保留；排版偏好、原文缺少标题或固定快照位置不单独判为失败。原文清楚且改写无实际收益时可以保留原文。

C 优先采用合格候选；没有可采用的合格稿且问题能依据完整已确认需求修正时，才发起一次自动修复。原生成器按有证据的意见作最小修改，C 再次执行全部检查；修复后仍有问题或修复已禁用时显示“需要复核”。修复意见不构成新的需求或操作授权。六类检查在同一轮 C 评审中完成；不含澄清、交接及重试时，A/B 生成至评审通常为 3 次模型调用，发生一次修复后为 5 次。

对话不设固定澄清轮数，每次发送或回答后由模型决定继续提问还是生成。主动“暂停并保存”后，发送按钮显示“继续对话 F2”：空输入且材料未变时重新打开未决问题，不增加模型请求；有补充或材料、历史变化时先更新需求快照并重新判断。结果完成后仅修改材料或历史，也可直接按 F2，沿用已确认需求而不添加虚构补充。恢复和后续补充沿用累计预算。运行时可以编辑输入，发送与材料修改暂时锁定；发送时冻结需求、材料和历史快照，旧版本结果不能覆盖当前成功提示词。

窗口少于 100 列时侧栏自动收起，按 F3 显示设置、材料和历史。Ctrl+N 新会话，Ctrl+R 回看报告，Ctrl+Q 退出。

运行时状态栏每秒刷新，分别显示正在工作的 A/B/C。没有模型活动信号时显示“等待响应”；仅在收到服务提供的推理片段时显示“正在思考”，收到正文时显示“正在接收结果”，正文收齐后显示“正在校验”，连接错误重试时显示“正在重试”。窄屏使用“等待／思考／接收／校验／重试”等短标签。界面不展示推理原文或尚未校验的正文片段；不提供推理片段的闭源模型可以一直显示等待状态。

## 材料与交接

材料支持明确添加的 UTF-8 文本、Markdown、代码及可提取文字的 PDF，保留用途、范围、来源、SHA256 和行号/页码。默认完整加载；相关片段模式按关键词选块，并显示部分覆盖。继续补充时从缓存完整块重新选择。已取消材料 20000 字符和需求与材料合计 50000 字符的固定限制；对话补充和合并提示词也不设固定字符上限，文件加载规模、模型上下文窗口及会话预算仍适用，详见文件材料说明。

普通网址、路径、“所给视频”“上述图片”等自然引用不会自动下载或解析。任务清楚时保留引用，不虚构素材内容；只有明确添加的本地文件进入材料加载器。材料中的命令和案例不扩大本次授权。

在历史区粘贴记录，或选择 TXT/Markdown 文件并按行填写路径。历史输入去除首尾空白后有内容，下一次发送就自动交接；清空后自动恢复普通生成。无效历史或文件会报错，不跳过历史继续生成。

同一会话切换流程时保留已确认需求、回答及累计用量。首次完整整理；明确的细节补充和冲突回答走增量更新。目标、范围或历史内容/顺序变化时重新完整整理。清空历史后移除活动交接快照、历史问题和窗口绑定；重新添加时重新整理，旧记录仅保留在报告中。

详见 [TUI 使用说明](TUI_WORKFLOW.md)、[交接说明](HANDOFF_WORKFLOW.md)和[文件材料说明](REFERENCE_FILES.md)。

## 预算与保存

普通与交接会话均不设累计模型时间预算或请求次数上限，连续澄清、多次提交和流程切换可继续推进。请求数、token 和耗时持续统计，只有“新会话”重置账本；等待用户回答、暂停和空闲不计入活动耗时。状态栏显示实际流程、阶段、已发请求数、耗时、已知 token 和未知用量。

模型响应没有整次调用或读取的硬性等待上限。首次活动前从请求开始计时，之后从最近一次非空推理或正文片段计时；空片段、角色声明和连接心跳不算活动。“等待较久”只提醒，可继续等待或手动取消。网络连接、发送及连接池超时等真实失败仍使用有限重试；中途断流丢弃该次未完成正文，下一次尝试独立接收。

流式优先；服务直接返回普通 JSON 时复用同一次请求，并在该会话后续使用普通调用。明确拒绝流式参数时，每个角色每会话最多增加一次普通调用回退，额外请求独立计账。token 上限可选，整个会话保持不变；失败或服务未返回用量时记为未知，设置 token 上限后会停止后续调度，包括回退请求。字符数只用于活动统计，不估算账单 token。每个会话最多自动修复一次提示词。

等待确认、暂停、成功、取消和失败都保存时间戳 JSON 报告到 `reports/`。只有当前有效版本的成功结果更新 `last_optimized_prompt.md`；取消、失败、待确认和旧版本保护上次成功提示词。保存失败保留界面内容，允许重试。报告包含原始需求及选中材料，按实际敏感程度保管。

每次请求的报告记录角色、请求编号、尝试编号、调用方式、首个及最近活动相对时间、推理与正文字符数及终止原因，不保存推理原文。等待用户回答、暂停及本轮结束时停止计时；新会话清空状态。缺少这些新字段的旧报告仍可回看。

首版只支持报告回看，不恢复退出后的会话。真实调用会将已确认需求及所需材料发送到配置的模型服务，默认关闭自动云追踪。

CLI 验证见 [依赖与兼容性记录](COMPATIBILITY.md)，界面及历史验证见 [TUI 验收记录](TUI_ACCEPTANCE.md)。回归覆盖命令行输入与退出码、流式活动、普通调用回退、取消、固定 A/B 与评审、自动交接、预算累计、引用保留、版本保护和 80×24 窄屏交互。离线测试证明流程和兼容，不证明真实模型语义质量提升。

`tests/legacy_optimize.py`、`tests/legacy_launcher.py` 仅为旧回归测试夹具，没有可执行入口，产品不导入它们。评测脚本 `evaluate.py` 和 `evals/` 是开发工具，默认不调用模型；`baseline` 单独使用 A 作一次生成对照，`quality` 检查当前 A/B 与评审链路。`evaluate.py` 保留独立的整组 `--call-budget`，移除单样例的 `--max-requests` 与 `--timeout`；真实探针的测试费用与等待保护由探针自身执行，不影响产品会话。课程结论和当前验收文档随源码发布；测试、探针及公开说明引用的九份基线一并保留。其他历史源码快照、个人报告及运行产物继续保存在本地，不进入上传清单。依赖用途、组件接入和评测原则见 [依赖与兼容性记录](COMPATIBILITY.md)。

GitHub Actions 配置在 Windows / Python 3.14 的干净环境中创建项目 `.venv`、安装依赖并运行离线回归；不需要配置模型密钥。远端运行结果以仓库 Actions 页面为准。

## 主要文件

- `prompt-optimizer.cmd` / `cli.py`：命令行需求、终端澄清、管道、JSON、材料预览和报告回看。
- `启动提示词优化器.cmd` / `launcher.py`：直接启动 TUI；`optimize.py` 为同一界面的旧文件名兼容入口。
- `tui.py`、`tui.tcss`、`tui_clipboard.py`：界面、样式和 Windows Unicode 复制。
- `optimizer_dialogue.py`、`optimizer_engine.py`：会话控制、澄清、生成、评审和共享预算。
- `optimizer_handoff.py`、`optimizer_documents.py`：交接快照、增量归并和本地材料。
- `optimizer_reports.py`、`optimizer_io.py`：报告、保存保护和原子文件写入。
- `optimizer_config.py`、`optimizer_models.py`：配置校验和模型适配。
- `optimizer_prompts.py`、`optimizer_layers.py`、`optimizer_examples.py`、`optimizer_selection.py`、`optimizer_review.py`：输出契约、提示模板、材料政策、示范选择和独立评审。
- `baselines/`、`course_analysis/`：公开所需的九份基线及课程结论；其他历史基线仅本地保留。
- `tools/prepare_repository.py`、`tools/repository_policy.json`：上传预检、精确清单及干净源码包。
