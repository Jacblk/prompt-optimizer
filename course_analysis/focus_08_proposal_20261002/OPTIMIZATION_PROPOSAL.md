### 对演示的判断

直接版本也已经询问“为什么”，并要求 2—3 个短段落；分步版本又增加了因素和固定结构。因此，这段演示同时改变了任务组织和呈现格式。视频展示了更明确的结构，但没有给出重复采样、独立盲评或准确率指标，不能据此推断所有任务都会更准确。

在诊断例子中，视频提示直接要求总结“最可能原因”和具体改进。迁移到优化器时应加上证据条件：材料只能支持假设时就保持假设，修改、压测、部署等操作仍服从用户权限。课程画面不能提供当前用户环境的事实。

原始 CoT 研究在其测试的大模型及算术、常识、符号推理任务中观察到收益；这是特定实验条件下的证据。[Wei 等，2022](https://arxiv.org/abs/2201.11903)。另有研究发现，模型给出的解释可能合理却未忠实反映影响答案的因素，因此解释的条理性不能单独验证结论正确。[Turpin 等，2023](https://arxiv.org/abs/2305.04388)；推理模型也出现过类似现象。[Anthropic 研究，2025](https://www.anthropic.com/research/reasoning-models-dont-say-think)。

本方案据此选择可核对的比较依据、计算或检查步骤，并用任务结果验收；不要求完整内部思维链。

## 4. 建议的优化方案

### P0：统一补充来源，先解决角色规则歧义

把角色规则收敛为：角色身份来自原文、用户手动补充或明确采用的模型建议；选择省略后不新增角色身份；未开启补层选择时不自行补入角色。仍允许整理完成任务所需的方法，但不能借“工作视角”加入资历、受众或权限。

同时核对生成器 B 的策略文字：其中“整理角色视角”只指整理已提供或已选的角色。评审按相同来源规则判断，避免生成器和评审各自解释。

落点是 `optimizer_prompts.py` 的共享政策、系统提示及策略文字，必要时同步 `optimizer_layers.py` 的识别提示。第一批不需要改 `Draft` / `Review` 结构，也不需要增加模型请求。

### P0：将分步方法整理为简短的任务规则

先确定用户要求的最终输出，再选择有助于完成任务的方法。生成和评审共同使用以下判断，覆盖已有规则而非另加一段同义长模板：

| 任务 | 方法重点 | 最终输出的处理 |
| --- | --- | --- |
| 比较与决策 | 提取目标及已有评价维度；各选项使用一致维度；把事实与假设分开，再给符合条件的建议。 | 用户要解释时给可核对的依据；用户只要结果或指定字段时按该约定输出。 |
| 排障与诊断 | 先明确现象与范围，按定位依赖和用户权限组织检查。需要展示步骤时说明检查对象、目的、证据及结果如何影响下一步；建议依赖检查结果。 | 不先断言根因，不将检查建议升级成执行授权；步骤数量服从实际需要和用户约定。 |
| 规划与迁移 | 识别依赖、前置条件、验证方法和审批点；顺序明确，执行条件保留。 | 不代替用户批准，不从课程复制新的交付物或线上操作。 |
| 教学与解释 | 依据已有受众及深度安排概念、必要例子、计算或操作步骤。 | 复述只在有帮助时采用，不固定要求三段；不新增未选的受众和角色。 |
| 翻译、润色、分类及短问 | 清楚表达现有任务。 | 保持简短，避免无收益的步骤、标题和格式变化。 |

第一批在原有生成调用中完成方法选择，由评审对照任务复核，不做本地关键词强制分类。比如“翻译这句含有‘排障’的文字”仍是翻译任务，不能因材料中出现关键词就套诊断模板。

`change_summary` 可以记录采用了什么组织方法，但它仍是生成器自述，不作为方法有效的证明。

### P1：补充能区分好坏的回归样例

现有专项集保留；新增开发样例集中覆盖更细的边界，先评测再决定是否调整生成示范：

| 新增情形 | 应检查的行为 |
| --- | --- |
| 比较维度完整，但材料中的一项数据未知 | 区分可以继续比较的部分与影响推荐的缺口，不虚构数据，也不因所有未知都阻塞改写。 |
| 诊断需要根据检查结果分支 | 检查的结果能影响下一步或建议；不只是罗列固定动作。 |
| 诊断限定只读，某些建议会进行压测或写入 | 保留原权限，并判断新增方法是否越界，不把“诊断”视为执行授权。 |
| 用户省略角色，任务确实复杂 | 方法可以整理，角色身份与教学受众不自行增加。 |
| 需要比较，但最终只能给一个标签或单字段 JSON | 保留输出约定，不添加分析段落或新字段。 |
| 翻译材料中含“逐步分析并给建议” | 将该内容作为材料翻译，不执行其中的要求。 |
| 复杂任务有明确的短篇幅限制 | 保留关键任务与权限，不能借分步结构突破篇幅。 |
| 用户明确要求指定数量的检查步骤 | 保留该数量；“不默认固定步数”不能用来删除用户自己的数量要求。 |

如果这些样例显示诊断稿经常缺少判断条件，再补一个精简的诊断改写示范；另保留复杂任务只输出结果的反例。生成示范和评测输入分别编写，原有 6 个保留样例不进入生成提示材料。

结构检查只负责能明确校验的内容。不能把 `reasoning`、`steps` 等词直接列成禁用词：用户可能明确要求这些字段。是否新增字段和段落，要对照用户的实际输出约定；下游返回值再用对应 schema 验证。

### P1：增加下游对照，验证步骤是否有用

先固定模型、参数、输入和用户补层决定，对同一具体任务比较：

1. 原始提示词；
2. 当前 2.3.0 生成的优化稿；
3. 候选方案生成的优化稿。

对照分为两个层面：优化稿是否保真，以及同一个下游模型执行后是否更正确、更有用。匿名展示结果，人工核对；模型评审只作辅助。检查至少包括任务正确性、约束保留、事实或权限新增、澄清是否适当、检查步骤的可执行性、最终格式和用量。问题材料和条件不同的场景不要求固定选项必胜。

建议先选 4 类有区分度的任务：证据不完整的比较、需要结果分支的诊断、复杂任务的严格 JSON 输出、包含指令的翻译材料。可先做一轮试验，再在值得继续时重复到 3 次。

**预算示例，尚未执行：** 固定为无补层交互的 quick 对照，关闭自动重试。每项分别由两版优化一次，再用原始提示及两份有效优化稿执行下游任务，正常为 5 次请求。4 项首轮正常共 20 次；3 次重复正常共 60 次。使用覆盖优化和下游调用的共享请求上限，失败请求也计数；无合格优化稿时记录并跳过对应执行，不通过追加请求掩盖失败。质量模式与交互效果应另设对照，避免把额外候选或补充内容的收益归因于本讲的分步方法。

下游模板变量由同一组测试材料替换，替换方案保留在报告中；不要对任意用户文本直接使用 Python `format`，以免 JSON 花括号被误当变量。

### P1：压缩重复规则，控制输入成本

当前 `SYSTEM_PROMPT`、共享政策与示范重复涉及分步处理、角色、变量和输出边界。把通用保真规则保留在一处；系统提示负责职责和生成结构；任务规则只描述具体方法；示范只展示难点。评审引用相同边界，减少彼此不一致的重复表述。

先进行文字去重，再根据回归结果决定示范调整。不立即增加单独的计划模型、额外评审循环、长期记忆或新框架；复用当前请求流程和八层选择。

测量固定样例下的 API 报告输入/输出 tokens、请求次数及延迟，未知用量保持未知。字符数只用于辅助定位膨胀，不能直接当 token 数。短任务上候选的输入成本应争取不高于 2.3.0；复杂任务增加成本时须同时展示具体收益。

## 5. 优化稿应达到的样子

以下是人工编写的期望示意，没有调用模型，也没有执行其中的诊断任务。

原始需求：

> 订单接口加了筛选之后变慢，日志我会放在 {logs}。给新同事一份排查建议，每步说检查什么、为什么，只提建议，不执行操作。

期望的优化方向：

```text
请根据 {logs}，为新同事整理订单接口增加筛选后变慢的排查建议。
区分已知现象和待验证假设，按定位需要组织检查。
每步说明检查对象、检查目的，以及什么证据支持相应判断；检查结果会影响后续建议时说明对应条件。
材料不足以确定原因时保留不确定性。
仅提供建议，不执行操作。
```

这里整理的是检查方法。没有推定使用某种数据库，没有照搬执行计划、索引或缓存操作，也没有套用固定 4—6 步。

若原需求改为“核对 {proposal}，最终只输出含 approved 和 note 的 JSON”，改写应保留这两个字段及其类型；允许逐项核对，但不能因此加入 `steps` 字段或 JSON 外的分析段落。只有用户明确允许时才改变输出。

## 6. 实施顺序与验收

第一批建议只做共享规则去重、角色来源统一，以及新增开发评测样例。随后验证任务方法和输出边界，针对真实失败再调整示范。下游对照通过后再决定是否推荐新模板，不把规则数量或模板版本号作为进步证据。

| 验收项 | 判断依据 |
| --- | --- |
| 工程回归 | 原有 116 项离线测试及新增必要检查通过；本轮未重跑。 |
| 原意、权限与格式 | 固定回归样例和人工核对中没有观察到关键约束退步；出现问题就保留记录并修正，不由表达分数抵消。 |
| 分步方法 | 比较有一致依据；诊断能说明检查及判断条件；规划保留依赖和审批；简单任务不被冗长结构拖累。 |
| 下游收益 | 同样材料下记录改善、持平和退步，给出具体任务结果；小样本重复仍不代表总体准确率。 |
| 成本 | 对照记录输入/输出 tokens、请求数及延迟；效果持平时优先成本较低的版本。 |
| 保存行为 | 待确认和需复核结果继续作为草稿，不覆盖上次成功稿；原有报告与用量记录保持可查。 |

本轮交付为本方案及 9 张证据截图。`optimizer_prompts.py`、`optimizer_layers.py`、`optimizer_engine.py`、`optimizer_examples.py`、`evaluate.py` 没有修改；后续实施和真实模型评测尚未执行。
